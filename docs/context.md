# 上下文管理与滚动摘要

解决两个问题：上下文**按条数截断**不可控；长对话后模型**突然失忆**。

## 改造前的做法

```ts
const HISTORY_LIMIT = 20   // 固定取最近 20 条
```

| 问题 | 后果 |
| --- | --- |
| 按条数而非 token | 20 条短消息约 600 token，20 条长消息可能 6000 token |
| 无溢出处理 | 第 21 条起被硬切断，模型无提示地失忆 |
| 网关只做路由 | `CONTEXT_TOKEN_LIMIT=1200` 仅用于"走端侧还是云端"，不截断 |

## 改造后的分层

```
消息进来
  ↓
从最新往前累加 token，直到超出预算
  ├─ recent   → 进 prompt（原文）
  └─ overflow → 压缩成摘要，累加到 Conversation.summary
  ↓
prompt = persona + 会话摘要 + 记忆事实 + recent 原文
```

| 层 | 存放 | 何时使用 |
| --- | --- | --- |
| recent 原文 | `Message` 表 | 每次带入 |
| 会话摘要 | `Conversation.summary` | 每次带入（很短） |
| 事实记忆 | `MemoryItem`（kind=fact） | 关键词召回 top3 |
| 文档知识 | `MemoryItem`（kind=doc） | 预留，按需检索 |

## 为什么摘要不进知识库

| 维度 | 摘要 | 知识库 |
| --- | --- | --- |
| 归属 | 单个会话 | 全局共享 |
| 用法 | 每次必带 | 按语义检索 |
| 风险 | 无 | 混入对话会污染检索，且要严防跨用户串号 |

摘要是"压缩后的上下文"，不是"外部资料"，所以放在会话字段上，而不是记忆表。

## 关键实现

### token 估算（`src/lib/tokens.ts`）

不引入 tokenizer，按中文 1 字 ≈ 1 token、其他字符 ≈ 0.34 token 估算，宁可高估。

### 预算切分（`src/lib/context.ts`）

```ts
export function splitByBudget(messages, budget = 1200) {
  // 从最新往前累加，超出即停；至少保留最新一条
}
```

预算用环境变量 `MESSAGE_TOKEN_BUDGET` 调整，默认 **1200**（配合网关 1200 的 token 路由阈值）。

### 摘要合并

模板生成，零模型调用、零延迟：

```
摘录用户消息的前 14 字
  → 去重
  → 条数 ≤ 6 全留；否则保留「开头 2 条 + 结尾 4 条」
  → 与旧摘要拼接，超过 180 字保留最近部分
```

保留开头的原因：只留结尾时，摘要在长对话里会退化成"最近说了什么"，丢失对话起点。

### 避免重复摘要

`Conversation.summaryMsgId` 记录已覆盖的最后一条消息 id，下次只处理更新的消息。

## 实测数据

用 26 条消息、预算 300 token 测试（刻意压低预算便于观察）：

```

summary = 第1条…、第2条…、第9条…、第10条…、第11条…、第12条…
```

注入后的 persona：

```
你是一个名为沐雪的可爱AI女孩子

之前聊过：第1条…、第2条…、第9条…、第10条…、第11条…、第12条…
```

## 效果与代价

| 项 | 数值 |
| --- | --- |
| prompt 增量 | 摘要 ≤ 180 字（约 180 token） |
| 额外延迟 | 0（模板摘要，无模型调用） |
| 数据库 | `Conversation` 增加 2 个字段 |

## 局限

| 局限 | 说明 |
| --- | --- |
| 模板摘要不"聪明" | 只是线索拼接，不总结语义（如"他在纠结换工作"） |
| 摘要不区分 AI 发言 | 只摘用户说的话，可能丢失 AI 的承诺（如"明天提醒你"） |
| 无相似度去重 | 重复话题会在摘要里重复出现 |
| 摘要不可回溯 | 累积后无法还原原始摘要 |
